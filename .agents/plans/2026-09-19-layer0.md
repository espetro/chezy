# Plan: Layer 0 nuclear core (2026-09-19)

> Status: draft, pending human review. Per `AGENTS.md`, non-trivial implementation waits on a
> reviewed plan. Target: the closed loop works end to end by 21:00 tonight.

## Objective

Ship the smallest self-contained demo loop: deterministic fixture -> dual-view UI -> swipe right
-> voice execution -> calendar confirmation. If any link is missing, there is no demo.

Success is a single scripted run that never blocks on the network:

1. Radar shows `mock_properties` cards.
2. Card 1 shows the amber forensic warning (lightwell).
3. Swiping right on Card 2 opens the Execution Modal, drives a transcript, and returns a booked
   timestamp.
4. The confirmation toast fires and the mascot animates.
5. The top toggle switches to Concierge, which shows the reasoning plus a "View on Radar" card.

## Conflict decisions (bake these in)

The source brief was written against a React/Vite + Framer Motion + JSON stack. The repo has
already committed otherwise. Decisions:

| Topic | Brief said | Decision for chezy | Why |
| --- | --- | --- | --- |
| App stack | React / Vite | **Next.js 16 App Router in `apps/web`** | Repo is a `vercel/chatbot` fork; a second build target doubles the surface for no demo gain. |
| Motion | Framer Motion swipe deck | **`framer-motion` allowed for the Radar deck only** | Recorded exception to `.agents/docs/design.md` ("no framer-motion on day 0"). The swipe is the signature interaction and the panel includes a design-systems judge. Scope the exception in the PR body; do not spread motion elsewhere. |
| Fixture format | `mock_properties.json` | **Valibot schema in `packages/contract`, typed fixture module** | Zod is banned; `.oxlintrc.json` enforces it. A validated TS module avoids `*.json` being flagged `linguist-generated` by `.gitattributes`. |
| Model access | Nebius OpenAI-compatible endpoint | **Nebius registered as a provider in `apps/web/lib/ai/models.ts`; keys read via `packages/config`** | `process.env` reads are banned outside `packages/config`. AI SDK 7 is already the transport. |

## Scope: files and changes

Complexity: `S` <= ~1h, `M` ~2 to 4h, `L` > 4h.

### Contract (`packages/contract`)

- `src/property.ts` (new, `S`): Valibot schema for a card: `id`, `title`, `priceEur`,
  `cadastralSqm`, `geolocation`, `floorPlanUrl`, `truthTags[]`, `forensic`.
- `src/forensic.ts` (new, `S`): `ForensicVerdict` = `truthScore` (0 to 100), `warnings[]`,
  `sunlight` enum, `priceVsNeighborhoodPct`.
- `src/booking.ts` (new, `S`): `BookingRequest`, `BookingResult` (`status`, `slotIso`, `channel`).

### Fixture (`apps/web`)

- `lib/fixtures/mock-properties.ts` (new, `S`): Card 1 lightwell trap, Card 2 Eixample gem,
  Card 3 Poblenou wildcard. Parse with the Valibot schema at module load so a bad fixture fails
  loud. Embed pre-extracted truth tags; do not compute GIS at runtime.

### UI (`apps/web`, Tailwind 4 + shadcn, tokens from `styles/tokens.css`)

- `components/chezy/dual-view-toggle.tsx` (new, `S`): `[ Concierge | Radar ]`, a single source of
  truth for the active view.
- `components/chezy/radar-deck.tsx` (new, `M`): framer-motion deck, left = feedback, right =
  execution modal. No `useEffect`; derive from props/state and handle the swipe in the event.
- `components/chezy/property-card.tsx` (new, `M`): price, cadastral square footage, floor plan,
  truth tags, amber `ForensicBadge` when `sunlight === "lightwell"`.
- `components/chezy/execution-modal.tsx` (new, `M`): drives the transcript and booking result.
- `components/chezy/calendar-toast.tsx` (new, `S`): "Viewing confirmed" toast with the booked slot.
- `components/chezy/concierge-panel.tsx` (new, `S`): chat history + recommendation card button.

### Wiring

- `app/(chat)/page.tsx` (modify, `M`): mount the toggle and both views in the existing chat shell.
- `app/api/forensic/route.ts` (new, `S`): server-only call that computes `ForensicVerdict` via
  Nebius; on error, fall back to the fixture's pre-extracted verdict.
- `app/api/viewing/route.ts` (new, `M`): initiates the viewing. **Layer 0 ships a deterministic
  `mock` mode that returns a fixed slot; the live SLNG path is a `live` mode behind env.** The
  demo must not depend on telephony.
- `app/api/calendar/route.ts` (new, `S`): creates the event; `mock` returns the booked `slotIso`.
- `lib/ai/models.ts` (modify, `S`): register the Nebius OpenAI-compatible provider.
- `lib/ai/forensic.ts` (new, `M`): prompt + structured output for the truth score.

### Config

- `packages/config` (modify, `S`): add `NEBIUS_API_KEY`, `NEBIUS_BASE_URL`, `VIEWING_MODE`
  (`mock` | `live`), `CALENDAR_MODE` (`mock` | `live`) to the Valibot schema.
- `.env.example` (modify, `S`): document the new keys, no real values.

## Build order (one concern per commit)

1. Scaffold (prerequisite, separate plan or the init plan).
2. `packages/contract` schemas + `mock-properties` fixture; a Vitest case proving the fixture
   parses and Card 1 resolves to `lightwell`.
3. Dual view with the toggle and static card rendering (no swipe yet).
4. Swipe deck + forensic badge; left swipe logs feedback only.
5. Execution modal + `/api/viewing` + `/api/calendar` in `mock` mode + toast.
6. Concierge panel + recommendation card; Nebius `/api/forensic` with fixture fallback.
7. Mascot + audio chime on booking success.

## Verification

- In-loop: `mise run validate:quick`.
- Pre-push: `mise run validate` (lefthook runs it; do not `--no-verify`).
- Manual scripted run of the five steps above with the network disabled, to prove the fixture and
  mock modes carry the demo.
- One Vitest case for the fixture parse and the Card 1 warning, and one pytest smoke only if
  `apps/scraper` is touched (it is not, this plan).

## Risks

- `RISK:` the framer-motion exception drifts into other components. Mitigation: scope the
  dependency to `radar-deck.tsx`; review flags any other import.
- `RISK:` `useEffect` creeps in for the transcript/audio analyser. Mitigation: use the
  `no-use-effect` skill; `useMountEffect` only for the analyser, with cleanup.
- `RISK:` committing to `apps/api` too early for voice. Mitigation: Layer 0 is a Next route
  handler in `mock` mode; decide `apps/api` only when live SLNG needs a long-lived socket.
- `RISK:` live telephony or Calendar OAuth on stage. Mitigation: `mock` is the default; `live`
  is opt-in and rehearsed separately.
- `RISK:` fixture drift from the real Idealista shape. Accepted for Layer 0; schema is the seam.

## Out of scope (later layers)

- Layer 1: live Nebius forensic calls, dynamic feedback pills and the preference vector,
  QualityClouds + Galtea runs, live SLNG call.
- Layer 2: wildcard injection, busy-line fallback badge, static typography badges.
- Explicitly cut: live GIS distance matrices, migrations, any tracker integration.
