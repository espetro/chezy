# 2026-09-20: JES-13 validated Devin retry

Branch `feat/jes-13/validated-devin-retry`, stacked on JES-12 PR #54. Surprises worth keeping:

1. **`GET /v1/sessions/{id}` keeps serving the previous `structured_output` after a
   correction message.** Without a content hash the retry re-validates attempt 1 forever. The
   machine treats "same hash as a judged candidate" as not-yet, and only a fresh hash as a new
   candidate; the attempt echo is then an ordinary validator error.
2. **Identical fixture listings collapse in `dedupeListings`.** The check script's four
   identical rows became one candidate on an empty database, so the mock returned a single
   listing id and the schema check refused it (the correction loop then correctly exhausted).
   Fixtures need distinct price and size. The JES-12 run had only passed because the shared
   `postgres` database carried the real dataset.
3. **A dedicated database per worktree again** (`jes13_qa`, `mise run db:seed` for the 300
   listings). `db:migrate` honours an explicit `POSTGRES_URL` over `.env.local`.
4. **Devin accepted first try in four live runs (14 to 28 s each, `max_acu_limit: 1`).** The
   genuine refused-first-candidate proof stays incomplete rather than staged; the loop is
   proven on labelled mock fixtures (`ADAPTATION_MOCK_SCENARIO`) in unit, pg0 and browser
   tests.
5. **Playwright `<details>`:** clicking a `summary` that is already open closes it; the e2e
   helper checks `.open` before clicking. Also `locator.innerText()` waits for the whole test
   timeout when the status region unmounts between `ready` and the panel refresh; pass a short
   timeout in polling loops.
6. **The sidekick was rate-limited twice**, so this ticket was implemented directly.
