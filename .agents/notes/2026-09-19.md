## Decisions made

1. **Frontend validation two-tier policy** (new, per user instruction):
   - **Tier 1 — app-level**: `agent-browser` (Vercel Labs, Apache-2.0, Rust CLI wrapping
     Chrome via CDP, npm: `agent-browser`) as the primary tool. **Pin in mise** as
     `"npm:agent-browser" = "latest"` so teammates get it on `mise install`. Fallback:

   - Two-tier structure: `validate:quick` (~10-30s, in-loop) + `validate` (full, pre-push).
   - Both `scripts/validate.ts` and `scripts/validate.py` **self-skip** when no relevant
     files changed vs `origin/main`.
   - CI uses `fetch-depth: 0` so origin/main is reachable.
   - Gate-tag enforcement test: `tests/test_agents_rules.py` asserts every `[gate: X]` in

   - Chezy adopts the **brioso** pattern (cheap-at-pre-commit staged when features land,
     full-at-pre-push, two-tier TS+Py). Rejects the oxe "everything at pre-push" pattern
     (AGENTS.md already contradicts that with the `validate:quick` gate marker).

3. **mise.toml tooling** (from mise-tooling audit, 2026-09-19):
   - Pin: `node 24`, `pnpm 12`, `python 3.12`, `uv latest`, `pg0 latest`, `ffmpeg latest`,

## Why these, briefly

- `agent-browser` gives stable `@eN` accessibility refs for LLM agents (no selector
  hunting), parallel sessions, and an optional `chat` subcommand for natural-language
  control. It's Vercel's reference impl. Pinning globally means every agent on every
  teammate's machine has the same version.
- `react-cosmos` is the right tier-2 tool because it runs each component in isolation,
  with its own mock context (no DB, no auth, no global state pollution). It's the
  fastest way to validate "does this single component render and behave correctly" when
  the surrounding app has broken state from a previous iteration.
- The validate-gate audit confirmed that `brioso` is the only sibling repo doing
  shift-left properly. Copying their pattern verbatim saves inventing it from scratch.

3. **pg0 installed via mise `http:` backend** (per user interrupt 2026-09-19):
   - pg0 is **not** on crates.io, **not** on npm, **not** on Homebrew — it ships only as
     GitHub release binaries (v0.15.2 has 7 platform assets: darwin-aarch64, darwin-x86_64,
     linux-{x86_64,aarch64}-{gnu,musl}, windows-x86_64.exe).
   - Chose `http:` backend with per-platform URL table over `github:` backend because
     `github:` can't disambiguate multi-asset releases cleanly and doesn't template the
     `v0.15.2` tag prefix.
   - Pinned to **0.15.2** (matching `vectorize-io/pg0` v0.15.2 release tag). Checksums
     deferred to `mise.lock` via `mise sync` so version bumps don't require manual sha256
     lookups. macOS arm64 + Linux x64/aarch64 (gnu) + Windows x64 covered; musl variants
     added the moment Alpine joins the CI matrix.
   - `mise install http:pg0` lands the binary at `~/.local/share/mise/installs/http-pg0/0.15.2/pg0`
     (renamed via `bin = "pg0"` from the per-platform filename). `mise exec -- pg0 --version`
     confirms `pg0 0.15.2`.
   - `apps/web/.env.example` now documents `POSTGRES_URL` matching the default pg0 URI
     (`postgresql://postgres:postgres@127.0.0.1:5432/postgres`); the old Neon reference is

## SLNG agent region surprise

- SLNG resolves an agent's LiveKit project from `(region, orchestrator)`; valid
  regions are only `us-east | eu-central | ap-south`. `housy` had drifted to
  `eu-west`/`pipecat` (no deployment → no SIP trunk attachable). PATCHing just
  `region` 404s because `pipecat` has no `eu-central` deployment — both fields
  must be patched together. Now pinned `eu-central`/`livekit` (`default-eu`,
  trunk `80ec46a8-…`), enforced by `ensureSlngAgentPinned()` +
  `mise run slng:agent:sync`. `us-west`/`eu-west`/`gb`/`br`/`il`/`za` are
  inference `X-Region-Override` regions, not agent regions.
