# 2026-09-20: JES-12 adaptive comparison panel

## What surprised

1. **The Devin key is v1 only.** An `apk_user_...` personal key returns `403 Forbidden`
   on every `/v3/organizations/{org}/...` endpoint and `200` on `/v1/sessions`. The client
   targets v1; `DEVIN_ORG_ID` stays in env for a future `cog_` key but nothing reads it.
2. **v1 has no `structured_output_required`.** A session can end without output; the
   machine fails the job instead of nudging (correction messages are JES-13 scope).
3. **Quota is a 403, not a 429.** `POST /v1/sessions` answered
   `{"detail":"Your organization has a billing error. Error: out_of_quota"}`. The client
   classifies 401/403 bodies matching `out_of_quota|out_of_credits|billing` as
   `out_of_quota` so the UI can say so honestly.
4. **JES-8 folds a second rejection of the same listing into the existing event**, so a
   check script that rejects one fixture listing three times gets one job three times.
   `scripts/check-adaptation.ts` uses one fixture listing per event.
5. **`Intl.NumberFormat("es-ES")` puts a non-breaking space before `€`**; test
   expectations need `\u00a0`.
6. **`sentenceCase` lowercases all-caps titles entirely** ("BRIGHT FLAT IN POBLENOU"
   becomes "Bright flat in poblenou"); it is not a proper-noun-aware title case.
7. **`mise run validate:quick` diffs `origin/main...HEAD`**, so uncommitted work is
   skipped and it reports "no TS changes". Run typecheck, oxlint, oxfmt and vitest directly
   while iterating, or commit first.
8. **Devin sessions can publish non-final structured output while `working`.** The
   machine accepts valid output in any phase but only treats invalid output as final once
   the phase is `finished`, `blocked` or `ended`.
